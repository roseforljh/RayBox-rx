# 普通 XHTTP 入口分类首轮（2026-10-30）

## 范围

指定俄罗斯测点经 CF 到英国自有源站，既有 32 候选加 2 个既有参照，共 34 IP。每 IP 单次普通 XHTTP、RX 关闭、原生 H2/正常 TLS、1MiB 自有资源、8 秒截止；总窗口 420 秒、最多 272 次出口 connect、每 IP 最多 8 次。用户明确授权此轮，无新网段扫描。实验使用独立目录和临时服务，没有重启旧实验 unit 或修改生产。

工具以环回 TCP 门控固定单个入口，保留 SNI/Host/TLS 字节流，但改变缓冲、反压与分包。此次只能作为该测量路径/时段的样本，不能冒充 Xray 直拨、永久受限分类或持续容量。

## 结果

| 项目 | 结果 |
|---|---|
| 应用请求 / 出口 connect 调用 | 34 / 34 |
| 包含冷启动的整轮耗时 | 143.181044 秒 |
| 完整 1MiB、HTTP 200、curl 0、identity、SHA-256 一致 | 12 个 IP |
| 其中达到 1MB/s | 11 个 IP |
| 另一个完整样本 | 0.926598MB/s，0.883672MiB/s |
| 完整样本最快 | 1.787218MB/s，1.704424MiB/s |
| TCP 建立但 0 应用字节 | 13 个 IP |
| 未观察到 SYN-ACK，门控 connect 失败 | 9 个 IP |

12 个完整样本共交付 12MiB，逐份字节数及 hash 已与现场源站同长度前缀核对。旧未执行分类草稿写的 hash 与当前源站不一致，此轮使用刚只读核实的实际前缀 hash，没有沿用旧草稿值。

**旧候选池确实混有普通 XHTTP 可以完整传输的入口。不能拿该混池此前 RX 吞吐证明“所有入口受限仍能提速”。** 12 个成功样本不能被称为永久不限速；13 个 TCP 成功但无应用字节的样本仅为后续失败/冻结候选，不能据此断言 TLS 完成或具体限流机制；9 个未观察 SYN-ACK 的样本不属于“已确认 TLS 可通的受限入口”。

## 成本及抓包边界

- 34 个唯一五元组+客户端 ISN 的 SYN 代际；52 个 SYN 包，其中 18 个同代际 SYN 重传；25 个代际观察到 SYN-ACK，9 个没有。与逐 IP 门控成功/失败计数一致，不能把“未观察 SYN-ACK”直接称精确丢包率。
- tcpdump captured 9621、received by filter 9624、kernel dropped 0。两计数相差 3，不能写“无捕获遗漏”或“线路无丢包”。
- SLL2、snaplen 128；6008 个记录截断。只能使用完整捕获的握手字段计数，TCP payload 捕获字节、IP 头声明字节、socket 字节和真实线上字节不能混用。
- TLS 握手次数、票据恢复、内部 XHTTP 请求/重试、去重完整 TCP payload 和真实物理线上流量仍缺可靠测量。TLS 1.3 加密记录数量不等于握手成功次数。
- 门控出口socket接收共12,725,807字节、发送106,782字节，应用交付12,582,912字节；这些差额包含TLS/协议及失败连接，不是可精确计费的线上额外流量。Linux各轮观察到的Xray CPU秒合计0.24、抽样RSS最高35,561,472字节；采样会漏短进程/峰值，未覆盖内核及curl总成本，不当作完整容量报告。

## 清理及协作核对

34 个样本 `cleanup_complete=true`，客户端和抓包进程已停止，无残留本轮 Xray 进程。英国两项临时服务均 inactive、MainPID=0，实验端口空；生产三个监听及 PID 与 preflight 一致。

另一会话独立只读核对了总报告、34 个逐 IP 文件、hash 参考、清理回读和 SYN 聚合算术；审查并纠正分析器的 IPv4 total_length 尾部填充误算。其没有重跑现场、没有独立从二进制 pcap 再统计，结论边界保留。

原始私有结果、抓包、命令、源站 hash 和逐 IP 清单只保存在被忽略的本轮 `artifacts/classify-field-20261030/`，不随本文发布。

## 与最终目标的关系

分类先排除了混 IP 误归因。此次没有运行 RX 提速验证，也没有完整 1GiB，不满足所有受限入口条件下 1 至 3MB/s 的最终目标。此前受限多地址 p128a 的 16MiB/85 秒仍不能作达标证据。

单连接有效数据方向已在本地做最小改动：只让完整数据已就绪的 RX 续段省去空响应头 Flush，首 open、未分段RX及未就绪续段仍立即 Flush，保留首上传依赖和认证/偏移语义。首刷新表测试与既有 H1/H2 分段上传、并发 TLS 定向 race 通过 1.461 秒；尚未部署远端，不承诺 CF 会减少一个包或吞吐提升。
