# 俄罗斯经 CF 到英国：HTTP/80 稳定性验证（2026-10-30）

本报告保留原测速快照及其明文控制信息的安全边界。后续新增 `rx.authKey` 控制认证加密、轮换实验凭据和独立速度复核，见 [HTTP/80 安全加固](xhttp-rx-security-20261030.md)。

本轮在用户提供的俄罗斯测点，经既有 13 个 CF IP 到英国源站，连续传输 185.219 秒，实际收到 **208,306,176 字节（198.65625 MiB）**，平均 **1.124647 MB/s（1.072547 MiB/s）**。用户在下载进行中将验收改为“差不多稳定即可”，因此约三分钟后主动停止，没有下载完整 1 GiB。

**关键条件：这轮使用外层 HTTP/80，加上 VLESS 的 `mlkem768x25519plus` 端到端加密。它没有证明继续使用外层 TLS 的方案达到 1 MB/s。** 这 13 个 IP 来自此前的受限 TLS 入口池；不能把某个端口的受限分类外推到同一 IP 的所有协议。HTTP 路径、请求头和 RX 控制信息在外层可见，内容加密不等于 HTTPS。

后续已补齐同一 HTTP/80 路径的逐地址普通 XHTTP 对照：**13/13 个地址完整 4 MiB、哈希一致，扣除首字节等待后的正文速度全部为 0.607–0.660 MB/s**。所以这轮不只依赖旧 TLS 分类，也有 HTTP/80 普通下载低于 1 MB/s 的实测依据。对照在 RX 稳定性测试之后依次运行，不代表永久分类，也不能单独确定限速设备或机制。

## 安全边界补充

**达到吞吐目标不代表这套 HTTP/80 RX 已通过安全验收。** 本节已对照实测源码快照核实，尤其不能只用“正文有 VLESS 加密”来概括整体安全性。

- VLESS 使用带认证的正文加密，上行头内的 `data` 是其协议数据的编码载体，不等于用户业务正文已变成明文。仅观察外层 HTTP 头，不会因此直接获得 VLESS 私钥或解密密钥。
- 外层 Host、路径、会话标识、RX 偏移/确认信息，以及 `X-RX-Token` 均未受 TLS 保护。有抓包能力的链路观察者可以读取它们，识别、关联及定向阻断这类流量；HTTP 代理或被配置为记录这些字段的日志也可能留存它们。CF 本来就在其边缘终止常规 CDN TLS，因此 CF 能读取 HTTP 头不是去掉外层 TLS 才新增的能力；新增暴露主要在沿途链路。
- 当前 RX 会话控制使用直接比较 token 的认证方式，没有以不在线路明文传输的独立密钥对控制请求做消息认证。nonce 的格式检查和响应回显不等于给整个控制请求加签。掌握会话路径、token 和可见参数的一方可能伪造控制操作、替换分段连接或关闭会话，造成断流、重传及资源消耗；此判断来自源码，未在远端执行攻击验证。
- VLESS 正文的认证加密通常会使被篡改的业务密文在解密时失败，但不会自动保护外层 RX 状态与可用性。本次文件哈希相同只证明该样本实际传输正确，不能证明能抵抗主动攻击。

若继续保留 HTTP/80 方向，应单独设计并验证 RX 控制请求的认证、防重放和资源限制，所用认证密钥不能由明文 token 直接替代。敏感业务仍应保留业务自身的 HTTPS。本轮没有修改密码协议或把实验配置部署为长期服务。

## HTTP/80 同路径受限对照补证

先只读检查此前 8 MiB 和 16 MiB 普通 XHTTP 的配置与抓包：二进制、Host、路径、模式及 VLESS 账号均与 RX 样本一致；两次正文均由同一池内 IP 的一条主要下行 TCP 交付，主要连接实际数据期间的去重 TCP 速度分别约 0.615 和 0.611 MB/s。低速不能仅用启动耗时解释。该旧抓包的部分流量计数与正文存在采集边界差异，因此不作为文件完整性依据。

随后使用相同二进制、Host、路径、VLESS 加密和账号，仅关闭 RX 并逐个固定池内地址，顺序完成 13 个 4 MiB 下载。每个样本限制 15 秒、16 唯一 SYN 停止阈值；整个控制器限制 300 秒，所有后台实验服务也有独立运行时限。没有扩池、扫描网段或改为其他内容源。

| 指标 | 13 个样本汇总 |
| --- | --- |
| 实际正文 | 54,525,952 字节（52 MiB） |
| 完整且哈希一致 | 13/13 |
| 含启动的平均速度范围 | 0.521407–0.578145 MB/s |
| 正文交付速度范围 | 0.606961–0.660070 MB/s |
| 正文速度口径 | 字节数 /（curl 总时长 − 首字节时间） |
| 新建 TCP | 每个 3 次，合计 39 次 |
| 每个客户端退出、端口释放 | 13/13 通过 |

这证明这 13 个地址在相应样本时段的普通 HTTP/80 XHTTP 均低于目标速度，而相同池的并发 RX 样本达到 1.125 MB/s。它支持本时段的实际提速结论，不证明 HTTP/80 与 TLS 端口有相同的包数限制，也不把整条链路的限速原因归给 CF 本身。

补证过程中，两次普通 SSH 握手及一次 SSH 控制转发尝试失败，均未启动下载。最后直接连接两端，俄罗斯侧 SSH 改用其支持的较小 Curve25519 密钥交换，并继续校验既有 Ed25519 主机密钥；测速配置不受影响。没有通过英国转发下载流量。

本轮独立源码快照以 `c4a47f0` 为基础，只包含以下六个文件的改动：

- `transport/internet/splithttp/rx_buffer.go`、`rx_buffer_test.go`：一次复制已就绪的完整续段，覆盖环形缓冲跨界和数据所有权检查。

- `transport/internet/splithttp/rx_parallel.go`、`rx_parallel_test.go`：部分响应中断后保留尚未交付的已收前缀，从 `written` 继续补发；累计 ACK 仍只由上层实际消费推进，测试专门验证未消费前缀不会被提前 ACK。
