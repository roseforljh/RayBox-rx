# HTTP/80 RX 控制面加固（2026-10-30）

保留俄罗斯 → 既有 13 个 CF 入口 → 英国的 HTTP/80 传输，以及 VLESS `mlkem768x25519plus` 正文认证加密。新增独立的 `rx.authKey`，加密并认证 RX 控制请求和响应；不增加 TLS 握手或额外请求往返，不改变分段、并发及回放窗口。

本文件描述新的安全补丁。[原 HTTP/80 现场报告](xhttp-rx-http80-field-20261030.md) 中明文 token 的问题属于此前实测快照，不能把此前的吞吐验证当作这版的安全验证。

## 已处理的问题

| 旧行为与风险 | 新行为 |
| --- | --- |
| 明文 `X-RX-Token` 可被旁路观察者读取，继而伪造 ACK、恢复或关闭操作 | token、动作、偏移、ACK、代数、分段边界和能力确认进入 AES-256-GCM 加密信封；独立 PSK 不上线路 |
| 控制头可以被修改，响应确认可以被伪造或替换 | 请求和响应分开派生密钥；认证绑定 HTTP 方法、实际路径、会话、上传序号及响应状态，响应额外绑定请求计数器 |
| 已捕获的合法请求可以再次使用 | 有界滑动窗口接受并发乱序，拒绝重复计数器；请求时间偏差最多 120 秒；关闭会话不立即清除仍有效的防重放记录 |
| 服务端进程重启会丢失防重放缓存 | 新会话使用服务端重新生成的随机 capability，旧上传/ACK/关闭记录不能控制重启后新建的会话；响应使用标准库随机 GCM nonce，避免重复请求在重启后导致响应 nonce 重用 |
| 上行正文或 Header/Cookie 中的编码载荷可以先被篡改再进入上传队列 | 上传字节的 SHA-256 放入认证加密信封，服务端解码后、推进上传序号和入队前校验；摘要自身不能被替换 |
| 移除 RX 头可能诱导回退到旧协议 | 配置 `authKey` 的客户端必须获得有效 v2 响应，服务端拒绝缺失、混合或重复的控制头；不回退到旧 RX/普通 XHTTP |
| 无密钥的旧 RX 被误用于公网明文 HTTP | 公网无 TLS/REALITY 的 RX 拨号和 TCP 监听要求 `authKey`；拨号检查包括 `spreadAddresses`，不能利用环回目标绕过检查 |

依赖 Go 标准库的 HKDF-SHA256 和 AES-GCM，没有新增第三方依赖。每个客户端会话有随机 128-bit salt，以会话标识和方向派生独立密钥；请求使用不重复的计数器 nonce，响应由 `cipher.NewGCMWithRandomNonce` 生成 96-bit 随机 nonce。响应 nonce 带在线路信封内，请求计数器另加入响应认证数据，防止跨请求替换。

防重放状态为每会话固定 1024-bit 窗口，服务端记录总数最多 `max(64, 4 * maxSessions)`；未通过认证的请求不分配这类状态。控制信封有 2048 字符上限，沿用会话数、TTL、上传大小和终身重试等既有上限。关闭 RX 时保留普通 XHTTP 的上传行为，遗留 `authKey` 字段不会使普通上传要求 RX 摘要。

## 配置和凭据

两端必须使用支持本补丁的内核，并在实际生效的 `streamSettings.xhttpSettings.extra.rx` 对象中配置相同 `authKey`。值为密码学随机 32 字节的无填充 base64url 编码，共 43 字符。不得用 UUID、路径、已公开 token 或可猜密码派生，也不通过请求头、URL 或公开订阅分发。不同部署或不互信用户应使用不同密钥。

HTTP/80 模式仍须保留实际配置中的 VLESS 正文认证加密，不能改成 `encryption=none`。`authKey` 只保护 RX 控制面，并不把任意传输正文变成密文。保留外层 TLS 的配置仍须正常验证证书。

已在被 Git 忽略的 `artifacts/rx-security-20261030/ready-configs/` 准备两端私有配置，轮换实验 RX 密钥、VLESS 身份与密钥、公开路径和本地 SOCKS 密码。新路径与认证资料独立生成。配置只用于独立实验进程，不替换生产服务。远端实验目录权限 0700、配置 0600；本地服务器信息仍保存在忽略的 `artifacts/credentials/`。

环回监听可能位于公网反向代理后，程序无法仅根据绑定地址判断外部是否启用 TLS。此类公网 HTTP 部署同样必须配置 `authKey`。不要记录控制信封、上传数据头、认证 URL 或密钥；保持 `Cache-Control: no-store`，不让中间层缓存或改写控制头。

## 保留的安全边界

- Host、路径、会话标识、HTTP 方法、连接目的地址、字节大小和时序仍然可见；能识别、关联及阻断连接。CF 作为 HTTP 代理仍能读取这些外层信息。加密控制面无法提供 HTTPS 的全部隐私属性。
- 能丢弃或重置流量的一方仍可断流；认证失败会结束会话。此次修复防止观察者仅凭读到的字段伪造会话控制，不承诺抵抗链路阻断或资源型 DoS。
- 重启后的防重放缓存不是持久化的。120 秒有效窗口内重放旧 open 仍可能创建一个有 TTL 和数量上限的孤立会话，但无法获得新 capability，也不能用旧控制记录接管它。跨进程恢复仍不支持。
- 控制面 PSK 的泄露会破坏该部署的控制认证；这层 PSK 加密没有前向安全，日后泄露密钥也可能解开此前录下的控制信封。同一密钥的持有人属于同一信任域，不互信用户需要分开配置监听和密钥。正文安全性取决于实际 VLESS 配置，应用本身的 HTTPS 也应保留。

## 验证与实际速度

初版加固候选两次各完整下载 64 MiB，SHA-256 均匹配，平均为 1.080958 和 1.102224 MB/s；同一轮旧版基线为 0.730676 MB/s、587 次分段重试。样本顺序运行且基线有明显波动，不能据此声称加密让网络更快，也不能证明性能完全无损。候选的两次结果证明加密控制面后仍能达到约 1 MB/s。

最终版补充了重启后的随机响应 nonce、防止公网分散地址绕过密钥检查，以及关闭 RX 的普通上传回归检查。用轮换后的实验凭据再次单独完成 64 MiB：

| --- | --- |
| 应用请求 / 正文字节 | 1 次 / 67,108,864 字节，无内容压缩 |
| 含启动耗时 | 66.488992 秒 |
| 平均速度 | **1.009323 MB/s；0.962565 MiB/s** |
| 完整性 | curl 0、HTTP 200、字节数和源文件 SHA-256 一致 |
| SHA-256 | `55930abe0d7fa6b891e7897127fc663277b98357f1d75b15849f01af38900a82` |
| 分段 / 并发 / 回放 / 预连接 / MSS | 65,536 字节 / 16 / 16 MiB / 0 / 1440，与原配置相同 |

结果支持“加固后仍达到约 1 MB/s”，不支持“性能精确零损失”。线路在这些顺序样本间有明显波动；没有为追求更高数字继续调整速度或挑选时段。本轮没有下载 1 GiB，沿用用户缩短验证的要求。

### 多用户容量尚未通过

用户补充要求：必须考虑多人共用同一受限出口。家庭、企业、校园或运营商共享地址场景均可能存在这种拓扑。当前样本不能确定限速按单条接入线路、公网源 IP、运营商上级出口还是其他范围聚合，不得假定换用户或换公网 IP 就能线性增加吞吐。多个客户端共用英国节点的出口 IP，也不自动等于共用俄罗斯接入侧的限速额度。

实际两端实验配置的 `maxSessions` 均为 **1**；这是单用户实验配置。源站达到该数量后会拒绝新增 RX 会话，不能原样作为百人服务配置。会话数也不等于人数，一个人的多个应用连接可能形成多个 RX 会话。

若共享出口的实际总上限为 1 MB/s，100 个持续满载用户即使公平分配也仅约每人 10 KB/s，重试和控制流量还会消耗额度。多连接协议不能增加外部硬性总带宽。若每人维持一个现有配置的 RX 会话，100 个会话最多允许约 1600 个活动下行分段请求，并会分配约 1.56 GiB 回放缓冲；控制、上传、HTTP、客户端预取及系统内存另计。不能只把 `maxSessions` 调大就宣称支持百人。

后续容量验收必须覆盖多人共享受限出口，观察总吞吐、每人吞吐与公平性、延迟、全局连接/重试数量及两端 CPU/内存，并检查拥塞时是否出现重试放大。未完成这些检查前，不作百人容量或每人 1 MB/s 承诺。本次补充为代码/配置核对和验收边界记录，未执行百人远端压测。

收尾回读确认本轮四组实验（旧版基线、两次初版加固、最终版）的 client/server/origin unit 全部无活动进程；实验端口 80、18084、18090 已释放。两端原服务监听和 PID 与最终验证前相同，未替换或重启生产服务。

本地验证覆盖伪造、控制头缺失/重复/降级、方法/路径/密文修改、响应跨请求/会话替换、响应状态修改、方向反射、乱序与重复请求、过期时间、重启后旧 capability、上传篡改后的有效重试、H1 Header/Cookie/Body 上传、H2 下载及资源上限。相关普通检查、定向 race 和独立快照构建已通过。`go vet` 的 9 条 protobuf 含锁结构复制告警在原测速快照可同样复现，不属于本次补丁；未扩展修改上游 XMUX。
