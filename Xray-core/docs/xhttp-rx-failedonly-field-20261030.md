# 13个失败候选的RX直拨首轮（2026-10-30授权窗口）

## 条件

沿用指定俄罗斯测点经CF到英国自有源站。只使用分类首轮13个TCP已建立但0应用字节的IP，不混入12个普通XHTTP完整样本或9个无SYN-ACK样本。此筛选不等于永久受限或TLS后限流证明。

用户单独授权H2/H1各一次64KiB应用请求、45秒/档、150秒总窗及60秒清理。正常TLS验证；1344字节段、并发8、RX预热关闭，VLESS testpre两种入口均为0；每RX实例128数据GET、32次终身故障重试。实际首SYN512仅异步停止阈值，没有固定超量上界，控制/上传、4路hedge及外层VLESS重拨不全部受数据GET预算覆盖。

独立实验内核包含已就绪续段省去空Flush的本地改动，源站配置/二进制hash在准备阶段核对。没有替换生产、扫描新IP或重启旧实验unit。首次SSH banner EOF阻塞恢复后才准备并运行。

### H2

客户端日志20个TCP connected、0个TLS ready；抓包20个唯一首SYN、20个观察到SYN-ACK，无同代际SYN重传。服务端没有RX authorized记录。不能把问题归为后续分段或把已建立TCP当TLS完成。

协作会话独立包级复核发现：20条连接均只观察到一包下行TCP载荷，起点为服务端相对序列1448，声明载荷约1323至1325字节，前缀[0,1448)未在抓包中出现。后段早于客户端FIN约0.089至1.627秒，客户端累计ACK仍保持相对0，包括后段到达后的重复ACK。代表连接在首SYN后0.376秒收到[1448,2772)，立即回复ACK0、SACK[1448,2772)，到2.001秒FIN仍相同。SACK进一步支持客户端TCP栈已经选择性收到后段，尚无连续前缀可交用户态，与socket读取0字节相容。包起点没有可识别TLS头，不能当新TLS记录。2秒截止及4路hedge仍属于实验条件，现有证据不足以认定延长握手等待即可恢复。抓包缺失本身不能确定丢失位置、责任方或永久限制机制。

### H1

客户端日志44次TLS ready，其中43次恢复握手；记录49个TCP connected，客户端抓包48个首SYN、47个有SYN-ACK。日志与抓包连接计数不完全一致，需保留采集遗漏边界。

服务端有36次authorized，包含1次open和35次续段尝试，均走到first-data-ready；该日志位于Write/Flush之前，不能证明CF已收到数据。仅open保留header-only Flush。客户端记录36次续段请求，仅首逻辑段1344字节完成。curl记录内层HTTP响应头203字节、正文1139字节，余下2字节与VLESS响应长度一致，尚未逐字节解析验证；不能将205字节全称为隧道协议开销。后续多个段起点反复尝试，未获得完整续段响应头，最后终身重试预算耗尽。

部分续段socket只读218字节，不能单凭字节数证明所有TLS记录的语义。协作会话按整个抓包窗口合并服务端TCP载荷序列区间，在48条首SYN连接中筛出40条首个观测服务端载荷为218字节的连接：28条剩余首个前缀缺口1841字节，5条缺1448字节，7条在已观测数据范围内没有剩余缺口。33条的连续前缀仅218字节，其余7条为1508至1592字节。旧人工核对的“另12条缺1266至1448字节”无法复现，已撤回；3条存在捕获顺序中的序列起点下降，不能用第二包直接认定最终缺口。未按端口精确绑定日志连接ID，不能将这40条全部称为续段连接；无剩余缺口也不代表HTTP正文完整。

代表连接观察到连续前缀[0,218)，其后[218,2059)缺失，再见声明序列范围[2059,3065)的载荷，后包起点可见TLS外层type23、length950。type23也可能承载加密握手或票据，不能直接叫HTTP正文。代表连接累计ACK停在218，并回SACK[2059,3066)，到FIN仍不推进；SACK末尾多1可能含FIN序号，不能算作正文。ACK/SACK支持TCP栈已选择性收到后段、前方仍无连续前缀，无法证明某条大TLS记录只收到一半。CF终止客户端TLS，源站Flush边界不保证保留到CF发给客户端的TLS记录。响应大小/缓冲变化、缺失前缀的原因及位置仍待区分。**此次无法证明省去空Flush有收益，也不能排除该改动在受限路径上反而影响可交付性。** 本地已构建保留原空Flush的独立对照产物，未自行扩大远端窗口。

## 成本与证据边界

- H2客户端抽样RSS峰值34,123,776字节、CPU观察值0.02秒；H1为37,441,536字节、0.05秒。未覆盖所有子进程/内核成本。
- H2抓包183 captured/183 filter/kernel dropped0；H1为850 captured/925 filter/kernel dropped0。H1有75条计数差，不能称捕获完整或线路无丢包。
- snaplen128，仅作握手元数据及序列字段统计，不据截断payload推真实线上完整流量。TLS恢复数字来自Xray ConnectionState日志，不能由type23包数倒推。
- 协作离线ACK/SACK、SYN及H1前缀缺口统计留在忽略的 `artifacts/rx-pcap-review-20261030/review.py` 和 `summary.json`。脚本仅针对本轮little-endian classic-pcap、SLL2、IPv4，代表H1连接使用固定本地端口；含包数与tcpdump captured一致、分组计数相符等断言。初版及补充全窗口区间合并后各执行一次，本会话读取脚本及结果，未重复运行。本轮无端点四元组复用、无跳过包，218字节分组未见重叠载荷区间；脚本一般无法消歧同ISN连接复活或跨代迟到包，不支持任意长连接重组。
- H1有RX首协商后的upload/segment活动日志，但应用样本失败。HTTP200或TLS恢复成功均不能当吞吐验收。
- 按全部关闭socket日志汇总：H2发送5780字节、接收0字节；H1发送77,377字节、接收24,253字节，双向合计为应用正文的89.23倍。此口径含TLS及外层HTTP，排除TCP/IP头和重传，不能当完整线上流量。H1记录32次续段重试；TCP connected日志平均H2为1.63次/秒、H1为6.50次/秒。抓包内全候选IP按墙钟秒汇总首SYN峰值分别为2次/秒和9次/秒，均未观察同代际SYN重传；窗口边界及墙钟分桶不能外推长期峰值。

## 外部资料核对与归因限制

协作会话检索并核对以下原始来源，本会话未重复检索：

- [RFC 8446 §5.2](https://www.rfc-editor.org/rfc/rfc8446.html#section-5.2)：TLS 1.3按记录进行AEAD认证；不完整密文记录不能交付部分明文。这个规则无法证明本轮发生过某条大记录被截断。
- [Xray #6541实现说明](https://github.com/XTLS/Xray-core/issues/6541#issuecomment-5082355658)：恢复握手可以少传证书，没有提供本线路解除限制的对照。本轮43次恢复握手后续段仍失败，恢复成功本身不足以满足交付目标。
- [Cloudflare 2025-06-26说明](https://blog.cloudflare.com/russian-internet-users-are-unable-to-access-the-open-internet/)：报告俄罗斯用户访问受影响，列出H1/H2/H3；没有确定本轮计量层或证明证书/PSK方案有效，不能把其中16KB表述套作本项目通用阈值。
- [另一环境的并发握手观察](https://habr.com/ru/articles/1044396/)：真实Chrome、单家ISP及另一目标的3/4连接差异，不等同CF或原生Go TLS。不能据此认定本轮并发8必然触发同一机制。

对照需先保持H1、1344字节段及其他参数一致，仅切换原立即空Flush和当前已就绪续段合并行为；1024/576字节段属于独立变量，不能与Flush同时改变后归因。空Flush基线产物SHA-256为 `9c66cb7e7d58966fdc382226d0cbfb365bf9fcf73691f2da465f4d8cef60eff5`，仅本地构建及哈希核对，未部署或执行新窗口。
