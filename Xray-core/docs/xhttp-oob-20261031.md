# 原生 OOB 主通道与 RX 启动回退（2026-10-31 UTC）

这次改的是 Xray 应用内核的 TCP 拨号、TLS 首次写入和 XHTTP 启动流程，不需要修改安卓或 Linux 系统内核。OOB 已从独立辅助代理接入 Xray；sing-box 包装层继续使用已有 VPN 保护和网络绑定，只补充连接前的 MSS 设置。配置默认关闭，不改变现有配置的主通道。

## 新连接怎样处理

1. 普通 XHTTP 优先，主路径不开 RX 回放缓存。每条新 TCP 的第一次 TLS 写入，使用标准用户态 `MSG_OOB` 插入一个紧急字节。支持 ClientHello 之前和第一个字节之后两种位置，默认先尝试后一种。没有合入原先效果较差的“SNI 中间插字节”方案。
2. 每个候选有自己的 TCP/TLS/HTTP 启动截止。必须完成证书验证、匹配 H1/H2 协商，并收到 HTTP 200 响应头，才把连接交给上层业务。503、协议错误、重定向、无响应等不能冒充启动成功。
3. 默认最多尝试4个不同候选，每个最多2500ms；每次 HTTP 启动最多新拨一条 TCP，限制 HTTP 库内部隐式重拨。候选包含既有地址、OOB位置、H2/H1；默认只用配置地址，不扫描、不扩池、不改Host/SNI。
4. 失败组合短暂冷却，约1秒起、最多30秒；全部冷却就结束主路径尝试。只有实际收到至少32KiB下行数据后，才记为优选，记忆最多2分钟，失败立即撤销优选。它是进程内、按目标和配置隔离的状态，不是持久化的网络指纹数据库。
5. 主路径启动失败时，只向显式配置的 RX 备用传输回退。代理账号和正文加密仍由原来的出站配置提供，备用地址、端口、Host、path和RX参数必须与自己的服务端相符。没有配置备用就明确失败，不暗中更改安全协议。

H2成功连接可被后续会话复用，减少重复握手。H1可能另开上传连接；不能把所有双向业务描述成永久只有一条TCP。普通连接一旦开始传业务数据，不会重新播放到RX；中途断线仍需要上层重连，之后重新选路。HTTP 200也不能保证后续数据永不冻结。

## 配置入口

客户端现有 `streamSettings.xhttpSettings` 中使用显式 `packet-up`，保留原有TLS证书验证、serverName、Host、path和VLESS正文认证加密。在其 `extra` 中加入：

```json
{
  "oob": {
    "enabled": true,
    "positions": [1, 0],
    "httpVersions": ["h2", "http/1.1"],
    "tcpMaxSeg": 1440,
    "delayMs": 5,
    "maxAttempts": 4,
    "attemptTimeoutMs": 2500,
    "addresses": ["192.0.2.1", "192.0.2.2"]
  }
}
```

示例地址是文档占位，须换成已授权且能够服务同一Host的真实入口。`addresses` 最多64个不重复的IP字面量；省略时使用原目的地址。配置地址池时要求显式TLS serverName。`positions`只能为不重复的0、1；`httpVersions`只能为不重复的 `h2`、`http/1.1`，通过各候选自己的TLS配置选择，不让Chrome指纹覆盖所选协议。

`delayMs` 允许1至50，0取默认5；它是此前实验参数，其必要性和最佳值尚未单独验证。`maxAttempts` 允许1至8，`attemptTimeoutMs`允许100至10000，0分别取默认4和2500。重试只发生在业务上传开始之前；不会对已经发送的业务请求做不安全重放。

主路径必须是原生TCP、TLS和XHTTP packet-up，不支持REALITY、H3、Browser Dialer、FinalMask或downloadSettings组合。主路径的 `rx.enabled` 必须为false或省略。服务端普通XHTTP无需开启OOB。

### 显式 RX 备用

在 `oob` 对象内设置 `fallbackSettings`，类型与普通 `streamSettings` 相同，且必须使用启用RX的XHTTP，不能递归开启OOB。例如以下只是备用字段片段，账号、域名、密钥和path均需采用现有真实配置：

```json
{
  "fallbackSettings": {
    "address": "192.0.2.1",
    "port": 80,
    "network": "xhttp",
    "security": "none",
    "xhttpSettings": {
      "host": "your-domain.example",
      "path": "/your-existing-rx-path",
      "mode": "packet-up",
      "extra": {
        "rx": {
          "enabled": true,
          "authKey": "REPLACE_WITH_YOUR_32_BYTE_BASE64URL_PSK",
          "stallDetect": true,
          "maxReplayBytes": 2097152,
          "maxResponseBytes": 65536,
          "maxConcurrentSegments": 16
        }
      }
    }
  }
}
```

密钥占位不是有效配置。HTTP/80备用必须使用已有的RX v2控制认证加密及VLESS正文认证加密；也可以显式配置正常验证证书的TLS备用。不要为了回退关闭证书验证。备用仅在主路径启动失败后调用，不是对已开始业务连接的无损迁移。窗口、段长及并发只沿用本项目既有HTTP/80样本，不推广到所有线路。

### 平台与安卓接入

- Linux/安卓使用原生用户态 `MSG_OOB` 和连接前 `TCP_MAXSEG=1440`。发送原语不需要raw socket或Root；VPN保护和网络绑定仍由原sing-box拨号器执行。
- sing-box包装层拒绝主出站原生 `sockopt` 的既有规则保留。MSS通过内部TCP control回调，在保护/绑定之后、connect之前设置；UDP和监听器不受该回调影响。OOB不支持sing-box的detour或TCP Fast Open组合。
- Windows本机已验证紧急字节不混入普通TLS流，但该环境的Winsock不支持修改TCP_MAXSEG。默认1440设置失败会明确失败或走显式RX备用；`tcpMaxSeg=-1`可明确选择系统默认MSS，只用于已验证适用的网络。本机环回OOB测试采用-1，不据此宣称俄罗斯受限链路可省略1440。
- 其他系统的API实现可编译与现场可用性须分开记录，不能笼统宣称“全平台免Root实测通过”。安卓本轮只有源码交叉编译，尚未构建AAR或做手机实机验证。

## 本地验证

相关RX、OOB、TLS、ECH与ALPN定向race通过205个测试及子测试。新增验证覆盖真实TCP紧急字节隔离、H1/H2证书验证与完整回显、HTTP错误/响应头冻结重试、取消后不追加尝试、RX启动回退、冷却与有效数据后记忆。sing-box包装层的OOB回显与重载测试通过，TCP control回调测试确认不会影响UDP。Android arm64的Xray传输与配置包交叉编译通过。

测试命令和原始JSONL保存在被Git忽略的 `artifacts/oob-native-20261031/`。没有新增依赖，protobuf使用仓库现有生成器更新。未替换生产、未提交或推送。

## 原生接入后的现场结果

在项目既有俄罗斯测点，经CF的TLS/2083到英国临时普通XHTTP入口验证。客户端使用这次冻结的Xray源码，Chrome指纹、MSS1440、默认OOB位置和H2/H1候选，主路径关闭RX，不再经过独立OOB辅助代理。地址池仍为此前13个既有地址，没有扫描或扩池。每次冷启动重启独立客户端，进行一个有界1MiB业务下载；每档最多20秒、12次SYN。长测最多185秒、20次SYN。

六档均为HTTP200、identity编码、curl退出0、完整SHA-256一致；抓包中的SYN MSS均为1440。客户端数据进程的UID均为65534，不依赖Root发送OOB。服务管理和抓包由已有管理员会话完成，不等于手机实机免Root验收。六档全部在第一个候选成功，位置为ClientHello第一个字节之后、协议为H2；配置了13个地址不等于逐个验证了13个地址。这个有限样本证明了原生接入后的新连接能够工作，不能给出全网成功率或相对旧方案的提升百分比；现场也没有触发多候选重试或RX回退，这些分支的证据来自本地故障测试。

另一次长测在183.303秒收到91,414,528字节（87.180MiB），全程只有一条新TCP、一个OOB紧急包、SYN MSS1440，没有RX分段或恢复。源文件相同长度前缀、落盘文件与流式SHA-256均为 `6aad6722fa8031bda1c1581d5485a5e7857750390409df0e22de106248c67c46`。按curl的183秒预设截止退出28，未完整下载1GiB，不能记作整文件通过。客户端进程峰值RSS37.78MiB、累计CPU0.86秒，英国代理峰值RSS35.84MiB；每0.2秒采样。这是单连接实测，不是与RX的新旧代码内存A/B，也未验证多用户或整夜稳定性。

七档抓包统计的captured与received-by-filter相同、kernel dropped为0；snaplen为128，只用于TCP头部、MSS、URG和连接计数，未以抓包代替业务hash，也不据此宣称线上没有丢包。一次旧准备阶段因过早读取systemd降权前的UID而退出，当时尚未启动curl；修正等待监听就绪后才开始上表六档，该准备错误不计入业务连接样本。

最终独立只读审计确认两端临时unit、进程和实验文件句柄为0、实验监听空闲，原生产监听及PID保持；清理错误列表为空。没有替换生产、打AAR、提交或推送。本次主要改动位于Xray的splithttp、TLS/ALPN、配置和TCP拨号层，以及sing-box的Xray出站和TCP control桥接；普通配置默认不启用OOB。
